# Seating, rules, and import/export audit

## Fixed issues

- Required proximity could remain broken because random seating rejected moves that increased bench sharing. Rule priorities now take precedence over the sharing preference.
- Random proposals could miss available repairs. Generation now checks deterministic moves/swaps for affected pupils and searches coordinated placements for small problems, while preserving pins and exact-position rules.
- Present but unplaced students, unresolved personal rules, invalid/removed seats, and duplicate placements could disappear from warning checks. They now receive explicit diagnostics. Absent students remain excluded from active rule checks.
- Seat suffixes such as `:00` could alias `:0` and permit conflicting physical placements. Seat identities now require a canonical integer suffix.
- Student IDs matching JavaScript prototype property names could break rule evaluation. Student and placement lookups now use Maps.
- Rules broken across rooms were missing from ordinary seating views and weekly warnings. Cross-room checks now appear in the warning list; weekly generation also attempts joint distribution repairs.
- Daily manual edits left saved weekly warnings stale. Capturing a day now refreshes its warnings.
- Imported weekly data could contain inconsistent attendance, foreign memberships, duplicate placements, or malformed warnings. Validation checks these before application/export, while preserving valid disabled pinned seats with availability warnings.
- Leaving a weekly day could lose baseline pins for pupils absent that day. Pins are restored when leaving normally; deliberate unlocks remain unlocked.
- Changing rules while a weekly day was active could leave temporary absences in an unusable stale week. Such edits now restore manual attendance.
- Replacing a saved student list could preserve other rooms' placements for reused IDs. Replacement clears placements, pins, and hidden warnings in every room. Adding/replacing students restores manual attendance and discards the obsolete week.
- Legacy JSON import could fail to unpack compact layouts. Both project import paths now unpack compact data and validate the entire backup before changing state, instead of silently dropping malformed associated plans/lists.
- CSV detection could misread leading blank lines or multiline headers. Malformed quotes, duplicate headers, and ambiguous duplicate keys now receive explicit errors; split names preserve compound surname data.
- XLSX import now detects corrupt ZIP data/checksums, invalid shared strings, Excel error cells, duplicate rows, and inconsistent cell coordinates.
- Project validation rejects malformed assignment containers, empty identities, duplicate rule identities, and incorrect room ownership.

## Search limits

Rule repair is bounded to keep the app responsive. Deterministic repairs inspect a limited number of candidates; coordinated seating search applies to at most six movable pupils and twelve free seats, with a 50,000-node limit. Auto distribution remains heuristic. These checks fix the reproduced avoidable violations, but do not prove global optimality or impossibility for arbitrary large rule sets. Remaining violations stay visible as warnings.
